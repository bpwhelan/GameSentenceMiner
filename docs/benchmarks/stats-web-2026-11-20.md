# Stats, web and SQLite benchmarks

Measured November 20, 2026 on a Ryzen 7 5800X running Windows 11 build 26300, Python 3.13.2 and release-optimized Rust 1.97.0.

## Application workloads

The two workers used independent WAL databases with identical input. Each contained 50,000 historical Japanese lines, 20 lines in the current reading day, 365 daily rollups, 365 historical goal completions and 400 Anki notes with cards and reviews. Latency and process CPU are milliseconds per operation, reported as the median of five alternating rounds. A CPU value of 0.00 falls below the Windows accounting resolution. The [raw measurements](stats-web-2026-11-20.json) include the iteration counts, memory readings and SQLite query plans.

The Flask test client dispatched each request to its standalone handler. The Rust worker invoked the production report handler, template or embedded asset and serialized the reply. The comparison includes differences in algorithms, database access and serialization. Some calculations were already available through the desktop broker. TCP, WebView rendering, HTTP compression, a full running GSM process and its other workloads are outside the measurement. The in-memory Hyper test exercises HTTP framing, gzip, HEAD and conditional asset requests separately.

Before timing, the driver compares the decoded JSON responses. The imported rows have independently generated creation times, which it checks separately. The search-page timing measures rendering only. The daily completion benchmark removes the day's fixture entry before each call. Its wall time excludes this reset. Process CPU includes it. For both backups, the driver decompresses into a new database, runs SQLite quick_check and verifies both the line count and the imported totals.

The capture measurement uses the same Python sqlite3 driver on both databases to isolate schema and index costs. The native schema used 88 KiB more space on this fixture. It cannot predict the change in total desktop memory.

## Implementation decisions

- The direct gateway reads through the desktop's existing connection pool. Its bounded blocking work includes report generation, serialization and gzip. The heatmap reads only the fields used to count mined lines. Static kanji metadata and compressed assets are prepared at build time.
- The dashboard previously cast every timestamp in its range predicate. SQLite reported a full table scan and a temporary sort. The numeric path now searches the existing timestamp index. An indexed check detects profiles that still need the legacy cast. Projection queries read only the relevant rollup columns and restrict the date range when no lifetime target is configured.
- A current core schema needs a version read and an indexed check for missing languages. First adoption can inspect and repair a populated schema under a transaction. Vocabulary and Anki cache migrations have a separate version so disabling the feature preserves core history. The tests include simultaneous upgrades, future versions, rollback and retry.
- Current goal settings and historical goal dates share an index. The streak read stops at the first gap and reads only dates after fetching the newest settings. Daily completion checks for a duplicate, inserts the historical snapshot, and updates the current settings under one immediate transaction. Tests exercise retries, competing writers, timezone headers, and a forced rollback.
- Batch imports reuse one prepared statement. A source replacement and every accepted row commit together. The generic and Mokuro import routes use this writer. One test forces a constraint failure after the first new row and verifies that the previous import survives.
- The backup pins a SQLite read snapshot, copies committed WAL pages, verifies the temporary file, then publishes it atomically. The database writer can continue accepting changes. Raw and compressed snapshots share the same verification and durable publication code.

## Historical profile with a speaker-label rule

A disposable SQLite backup contained 166,611 lines, partial per-game rollups, explicit pauses and the custom punctuation rule `【.*?】`. The previous release forwarded the dashboard to Flask for this rule. Rust upgraded the copy from schema version 0 to 4, retained the line count, and passed SQLite's quick integrity check. All four full JSON responses matched Flask, including chart order and session counts, with a relative tolerance of 1e-10 or an absolute tolerance of 1e-8 for floating-point values.

These are median milliseconds per request over five alternating rounds of three requests after warming each handler. Both workers serialized the response locally. Timings exclude HTTP transport and compression.

## Reproduce

Run from the repository root with the development Python environment.

```powershell
cargo build --locked --release --manifest-path native/gsm-web/Cargo.toml --example report_benchmark
.venv/Scripts/python.exe -X utf8 scripts/benchmark_stats_web.py --rows 50000 --rounds 5 --output docs/benchmarks/stats-web-2026-11-20.json
```

See the [schema migration guide](../../native/gsm-db/README.md) and the [ownership catalogue](../RUST_MIGRATION.md).
