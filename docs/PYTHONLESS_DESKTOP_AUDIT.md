# What still needs Python in GSM

**November 21, 2026 · `codex/tauri-architecture` · working tree based on `4fea8c90`**

Normal desktop startup runs the Rust backend. An isolated Windows install and reopen exercised dialogue intake, SQLite persistence, the loopback gateway and the overlay socket with no supervised Python process. Qt windows use an on-demand host built from the same source revision as the desktop. Remaining sync work is outside this cutover.

The native dictionary importer reopened Electron-created Yomitan and Hachidori profiles and preserved their original files byte for byte. The full desktop compiled on Windows and Ubuntu under WSL. On Ubuntu, the native portable OneOCR engine read both Japanese dialogue lines in `GameSentenceMiner/test/GRlkYdonrE.png` exactly as the reference implementation did. macOS runtime behavior and a live OBS-to-Anki session remain unverified.

The desktop owns the overlay's scene, capture area, profile and settings updates. Reading hotkeys use the desktop input service. History text rewrites update the affected reading days within the same SQLite transaction. The package check verified 129.9 MiB of staged Windows resources, including the checksum of the on-demand Qt host.

For the Japanese screenshot, the median time from launching a fresh OCR process to exit was 0.30 s for release Rust and 0.84 s for the Python reference. Median peak resident memory was 152 MiB and 290 MiB respectively. These figures include loading the models. [Portable OneOCR measurements](benchmarks/portable-oneocr-2026-11-21.json)

I then sent one request for each distinct method/path pair to a freshly built, unoptimized Rust gateway on an ephemeral loopback port, with the Python upstream disconnected. The fixture used GSM's production database migrations and seeded game, goal, vocabulary, and Anki data. The reader callbacks were test doubles so requests could exercise dispatch without opening dialogs, contacting providers, or touching a live Anki collection. ## Distribution and cost before the cutover

The managed runtime targets Python 3.13.2 and uv 0.13.4. The project declares 64 base dependency entries before platform markers and extras. The release preparation path invokes `pip install --no-deps -e .` to build the PyO3 module.
