# Electron to Tauri overlay parity audit

**Historical findings:** implementation repairs and current verification are tracked in [Tauri parity repair status](TAURI_PARITY_REPAIR_STATUS.md). Built-in engine hooks were subsequently deferred by the user.

The baseline is the released Electron overlay in `v2026.11.0` (`cc3e429e`), which launches the overlay in a separate Electron process. The candidate is this workspace’s Tauri implementation on November 13, 2026. The comparison starts at the app’s launch paths and follows the overlay’s windows, settings, hotkeys, dictionaries, input, capture, and backend messages. The desktop integration section records adjoining shell coverage and gaps. The audit used an existing Windows development build and temporary profiles.

**Priority:** P0 blocks access, configuration, or a core overlay workflow. P1 is a shipped behavior gap. P2 is a secondary workflow or diagnostic gap. **Evidence:** “Reproduced” means observed on Windows. “Source” means the production code or protocol establishes the difference. “Verify” means a platform, runtime, or migration outcome still needs a test. “Deferred” means the migration already documents the behavior difference.

## Verification and fix order

The Windows `overlay`, `foundation`, `settings`, `workspace`, `home`, `notifications`, and `input` smoke runs passed. So did the OBS, Text Hook, Agent, and OCR status checks, both dictionary import/reopen runs, and both synthetic Electron-to-native dictionary transfers. The overlay test waits for a complete settings document, which can be evaluated while hidden. Its pointer path can dispatch synthetic hover and its VN Guide path injects fixture messages. Physical click delivery, the actual overlay settings shortcut, native Jiten service round trips, and packaged/macOS/Linux behavior still need verification. The Electron release’s settings and Jiten browser tests both passed from a temporary export of `cc3e429e`. The settings fixture covered 28 pages at three sizes, including navigation, save, and profile changes. The Jiten fixture used a loopback service and checked extension and renderer requests, batching, and controller grading. [Release settings test](https://github.com/bpwhelan/GameSentenceMiner/blob/cc3e429e/GSM_Overlay/tests/settings-electron.cjs), [release Jiten test](https://github.com/bpwhelan/GameSentenceMiner/blob/cc3e429e/GSM_Overlay/tests/jiten-electron-smoke.cjs)

`npm --prefix GSM_Overlay test` reported 665 passed, 39 failed, and 1 skipped. The failures grouped into 29 missing `GsmNativeLayout` references, 9 fixtures missing `nativeOverlay`, and 1 missing `furiganaDictionaryGeneration` reference. The production renderer loads the layout script and declares the dictionary generation. Repair the fixtures before using this suite as a parity gate. Existing Electron tests for tray lifecycle, settings, and Jiten are concrete scenarios to carry over to Tauri.
